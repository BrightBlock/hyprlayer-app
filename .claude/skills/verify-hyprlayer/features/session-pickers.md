# Session pickers: mode, model, effort, permission

Each chat tab has an agent mode (General, Research, Plan, Implement, Validate), picked from the coloured tile at the composer's left edge. The mode is fixed once the session starts. The focused chat's model, reasoning effort and permission mode sit in the status bar at the bottom of the window, not in the composer. The model menu groups models by harness (Claude Code, Codex, OpenCode, plus Ollama when configured), so picking a model also picks the harness. After a session starts, models from other providers are disabled, except on a start that never launched (session-failed-start.md). A tab opened for an existing session shows the session's own model, effort and permission mode, never this device's defaults. Changing the model or permission mode on a live session relaunches the harness, and asks first if a turn is running. Claude switches permission mode in place.

## Sub-features

- `pick-mode` changes the tab's agent mode before the first send. It's a read-only tile afterwards.
- `pick-model` switches model and harness on an unstarted tab.
- `pick-model-live` switches a running Claude session's model, which relaunches it with `--resume`.
- `pick-model-lock` disables other providers' models once the session has launched.
- `pick-session-seed` shows an existing session's model, effort and mode on a tab with no pick: the row's model (matched to the catalog whatever date or `[1m]` suffix `init` reports) and its `requestedPermissionMode`. A reopened tab relaunches in that mode. <!-- src: src/features/session/SessionChat.tsx:634 --> <!-- src: src/lib/domain/models.ts:144 --> <!-- src: src/features/session/sessionStore.ts:2090 -->
- `pick-effort` sets the reasoning effort. Claude models with effort tiers and Codex only.
- `pick-permission` sets the permission mode. Claude and Codex only.
- `pick-harnesses` opens Settings › Harnesses from the model menu.

## Gotchas

- The status bar shows the controls of the **focused pane's** active tab. Bridge clicks send no pointer events, so clicking into another pane doesn't move focus. Keep one pane open. <!-- src: src/features/session/sessionControls.ts:108 -->
- Menu rows are `button[role="menuitemradio"]` with `aria-checked`. Text strategy can land on the wrong row ("Auto" and "Ask each time" both match short text), so click by exact `textContent` in JS. <!-- src: src/components/OptionMenuList.tsx:106 -->
- On an ended session, the triggers are `disabled`: `interactive` is false, so no menu opens. A failed start keeps them enabled, and one that never launched offers every provider (session-failed-start.md). <!-- src: src/features/session/SessionChat.tsx:1528 -->
- While Claude plans, the pill is pinned to `Plan` and can't be clicked. <!-- src: src/features/statusbar/SessionControlsCluster.tsx:54 -->
- `Ultracode` is disabled unless the model supports xhigh. <!-- src: src/features/session/SessionChat.tsx:819 -->
- Model labels come from the live `claude` probe, so `Haiku 4.5` and `Sonnet 5` are fallback labels. Read the menu before matching.
- Don't trust the agent's own answer about which model it is. Read `list_active_sessions`.

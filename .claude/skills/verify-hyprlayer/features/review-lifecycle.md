# Review lifecycle steps

After an implement session finishes its plan's tasks, the app walks the workstream through Validate, Review and Ship. The Plan tab's header badge names the stage (`Implement`, `Validate`, `Review`, `Ship` or `Shipped`) with a detail line, and a body below it holds that stage's actions. The implement chat ends with a matching card: `Validate the plan`, `Validation found N issues`, `Validating in a new agent` or `Ready for review`. Validate runs the plan check in a new agent or as a subagent of the implement chat. It can also be skipped, and its findings can be fixed, accepted, or handed to a goal. Review shows viewed progress and fix rounds. Ship shows `Review approved`/`Not reviewed` and the PR row.

## How to get to it (user POV)

- Open the Plan tab for an implement or validate session ([plan-tab.md](./plan-tab.md)). The badge and body sit above the phases. <!-- src: src/features/review/LifecycleSteps.tsx:351 -->
- Scroll to the end of the implement chat for the card. It renders only once the plan's tasks are done and the agent is idle, and disappears once the review is approved. <!-- src: src/features/session/TranscriptView.tsx:1798 --> <!-- src: src/features/review/validateFlow.ts:119 -->

## Driving it with the MCP bridge

Preconditions:

- **Instance.** Use **shared** (`.dev`), or an isolated instance with one implement session: open a `Native chat` tab, set `Agent mode: Implement`, start one short Haiku turn, then `openPlanPreview` that session with a tracking plan (plan-tab.md). On a folder workstream the Review step reads `No changes to review`, and the chat card stays hidden because the diff is empty. In the `review_lifecycle` sandbox the right panel offers `Plan`, but it reads `Document is not in the thoughts index: thoughts/shared/plans/e2e.md`, so no lifecycle renders there. <!-- src: crates/hyprlayer-core/src/error.rs:300 --> <!-- src: src/features/review/ReadyForReviewCard.tsx:74 -->

- **Anything that starts an agent spends model turns.** Run those only in the `jtsiros/hyprlayer-live-tests` project, per ADR-0012 (agent timing). Never use a real project: name any doc it writes `zz-…`. <!-- src: docs/adr/0012-live-test-repo.md:12 --> This covers:

## Gotchas

- In a validate tab, the Plan tab shows the implement session's plan and restores that session first. Its steps may lag a beat after the tab opens. <!-- src: src/features/review/LifecycleSteps.tsx:167 --> <!-- src: src/features/review/ReadyForReviewCard.tsx:46 -->
- A settled step stays settled, so a later review round in the implement chat doesn't reopen Validate. To test Validate again, delete the store entry, not the session. <!-- src: src/features/review/validateFlow.ts:124 -->
- `Validate as subagent` waits a 5s grace period after its turn goes idle before it counts as finished. Don't read `validating` → `done` sooner. <!-- src: src/features/review/validateFlow.ts:35 -->
- When a met goal owns the next step, the chat card is hidden and the goal's card offers that step instead. <!-- src: src/features/review/ReadyForReviewCard.tsx:78 -->
- The validate step store is per webview profile. A step set on another desktop is reconstructed from the validate session's `parentSessionId`, not read from this store. <!-- src: src/features/review/validateStep.ts:59 -->

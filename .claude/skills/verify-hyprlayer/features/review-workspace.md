# Review workspace

`Review changes` replaces the chat with a full-width review of the workstream branch against its base. The header shows the review status, `N / M viewed`, a progress bar and `branch → base` with `+adds −dels`. A file tree on the left groups files by folder, or by plan task when the implement session tracks one. The diff pane shows one file at a time, with prev/next, a `Viewed` checkbox, a layout toggle, and empty states for binary and oversized files. The agent's notes and the reviewer's threads render inline in the diff. Notes, threads and the Submit popover are in [review-threads.md](./review-threads.md).

## How to get to it (user POV)

- In the right sidebar's Changes header, click the review icon (`aria-label` `Review changes`). It's hidden for folder projects. <!-- src: src/features/workstreams/ChangesPanel.tsx:579 -->
- Press `⌘⇧R` (`ws.review`) while a git workstream is open. <!-- src: src/routes/ProjectPage.tsx:1383 -->
- In an implement chat, click `Review changes` on the `Ready for review` card. <!-- src: src/features/review/ReadyForReviewCard.tsx:198 -->
- In the Plan tab's Review step, click `Review changes` or `Review N updated files` ([review-lifecycle.md](./review-lifecycle.md)). <!-- src: src/features/review/ReviewChecklist.tsx:137 -->

## Driving it with the MCP bridge

Preconditions:

- **The baseline `verify-demo` seed can't reach this.** A folder workstream isn't reviewable, and the review entry and Git panel are hidden. <!-- src: src/routes/ProjectPage.tsx:877 -->
- **Seed with the kept `review_lifecycle` E2E sandbox.** It's a git project `demo` with workstream `Review work`. Its review holds 7 files: a modify, a rename, a deletion, an unstaged `mv`, an untracked file, a binary blob and a 3 MiB file. It also has agent notes (one `outside_plan_scope`), sent threads on both sides, three rounds, and status `approved`. <!-- src: crates/hyprlayer-e2e/tests/review_lifecycle.rs:168 -->
- **It's isolated and costs nothing to run.** The harness is a stub `claude` pinned in the sandbox's own settings, and `gh` is pinned absent, so there are no model turns and no GitHub calls. <!-- src: crates/hyprlayer-e2e/src/sandbox.rs:12 -->
- **`verify.sh` doesn't automate this seed.** Launch it by hand: the app attaches to the sandbox's server through `hosts.json` `localProfile`, which is read once at startup. <!-- src: src-tauri/src/hosts.rs:135 -->
  1. From the repo root, run `cargo build -p hyprlayer-server`. Then run `HYPRLAYER_E2E_KEEP=1 HYPRLAYER_E2E_SERVER_BIN=$PWD/target/debug/hyprlayer-server cargo test -p hyprlayer-e2e --test review_lifecycle -- --nocapture 2>&1 | grep 'keeping the sandbox at'`. Without `--nocapture`, a passing test swallows that line. <!-- src: crates/hyprlayer-e2e/src/sandbox.rs:392 -->
  2. Serve the sandbox with `SB=<path>`, `REPO=$PWD`, and `(cd "$SB/daemon-cwd" && exec env -i HOME="$SB/home" USER=e2e LOGNAME=e2e PATH="$SB/bin:/usr/bin:/bin:/usr/sbin:/sbin" SHELL=/bin/sh TMPDIR="$SB/tmp" XDG_RUNTIME_DIR="$SB/run" GIT_CONFIG_NOSYSTEM=1 HYPRLAYER_APP_CONFIG_DIR="$SB/app-config" HYPRLAYER_APP_DATA_DIR="$SB/app-data" HYPRLAYER_APP_LOG_DIR="$SB/logs" "$REPO/target/debug/hyprlayer-server" serve) > "$SB/serve.log" 2>&1 < /dev/null &`. <!-- src: crates/hyprlayer-e2e/src/sandbox.rs:178 -->
  3. Pick `TS=$(date +%s)`, `ID=ai.brightblock.hyprlayer.verify-$TS`, `RUN=$TMPDIR/hl-verify/verify-$TS` and a free port in 1431–1449. Write `{"hosts":[],"active":null,"localProfile":"$SB/app-data"}` to `~/Library/Application Support/$ID/hosts.json`. <!-- src: src-tauri/src/hosts.rs:32 -->
  4. Write `$RUN/tauri.verify.conf.json` exactly as verify.sh's isolated heredoc does, with `$ID` and the port. Start `pnpm exec tauri dev --config` on it under verify.sh's `CLEAN_ENV` unsets, logging to `$RUN/dev.log`. Then write `$RUN/pid` and a `run.env` (`MODE=isolated`, `IDENTIFIER`, `VITE_PORT`, `PID`, `EVIDENCE=$REPO/target/verify/verify-$TS`), and `mkdir -p` that evidence dir, so `verify.sh doctor` and `cleanup` accept the run dir. <!-- src: .claude/skills/verify-hyprlayer/verify.sh:77 -->
  5. Ready is `connected to <adjective-animal>` in `dev.log`. <!-- src: src-tauri/src/supervisor.rs:180 --> Doctor's last two checks fail by design: `connected to this machine`, and the `$ID/hyprlayer.sock` owner. Check those by hand instead: `lsof -U | grep "$SB/app-data/hyprlayer.sock"` shows the sandbox server, and this app never spawns its own. <!-- src: src-tauri/src/supervisor.rs:226 --> <!-- src: .claude/skills/verify-hyprlayer/verify.sh:104 -->
  6. Teardown: run `verify.sh cleanup "$RUN"`. Then stop the sandbox server with the step 2 env and `hyprlayer-server stop`, and `rm -rf "$SB"`.
- **Read the state before driving.** Get the workstream id and `worktreePath` from `window.__TAURI__.core.invoke('list_all_workstreams')`, then save `window.__TAURI__.core.invoke('get_review', { workstreamId })` as `00-review.json`. <!-- src: src/lib/bindings.ts:126 --> Expect `status` `approved` and `viewed` `["src/new.rs"]` (1 of 7).

## Gotchas

- `Review changes` is also the `h1` text and the Ready card's button text, so select the header icon by `aria-label`, not by text. <!-- src: src/features/review/ReviewHeader.tsx:125 -->
- `Group by` (`Plan task` / `Folder`) only renders when the implement session's todos are tracked. The sandbox has no plan, so it shows folder groups only. <!-- src: src/features/review/FileTree.tsx:259 --> <!-- src: src/features/review/ReviewWorkspace.tsx:220 -->
- `Ship` appears in the header whenever there's no live PR. Clicking it opens the Ship check, not a push: see [ship-pr.md](./ship-pr.md). <!-- src: src/features/review/ReviewHeader.tsx:184 -->
- Changing a file in the worktree drops it out of `viewed`, because the stored oid no longer matches. A stray edit during the run moves the count. <!-- src: crates/hyprlayer-core/src/runtime/reviews.rs:464 -->
- Raw `set_review_file_viewed` skips react-query invalidation. Toggle through the UI, or reload before judging. <!-- src: .claude/skills/verify-hyprlayer/SKILL.md:60 -->
- `.hyprlayer/review/` and `.hyprlayer/settings.toml` never appear as review files: they're excluded. <!-- src: crates/hyprlayer-core/src/review/diff.rs:130 -->

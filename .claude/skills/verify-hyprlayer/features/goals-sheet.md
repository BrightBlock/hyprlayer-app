# Goal sheet: run until met

A goal runs an agent in a loop until a condition holds. Each iteration runs the work prompt, then the checks: shell commands, an LLM evaluator, plan boxes, or a validation session. It stops when the checks pass (`met`) or a limit is hit. The Goal sheet (`Start a goal`, `Edit goal` or `Extend goal`) has a section nav (`Goal`, `Checks`, plus `Phase N`, `Whole plan` and `Manual` for a plan). Its Goal page holds the condition, work prompt, limits (iterations, budget or tokens, active time) and `Run in`. Submit stays disabled, with a reason in its tooltip, until the spec is valid. A running goal shows a status-bar chip with pause, stop and edit.

## Sub-features

- `goal-open` opens the sheet from the composer's `Start a goal` button with a blank spec.
- `goal-validate` disables `Start goal` and gives the reason (no gating check, empty condition or prompt, bad limits).
- `goal-checks` adds, edits and toggles a command check, and toggles the evaluator.
- `goal-cancel` closes the sheet without creating a goal.
- `goal-run` starts the goal and runs it to `met`, with the chip and a read-back. **Spends model turns.**
- `goal-board-badge` shows the board card's `goal N/M` badge while a goal runs.

## Gotchas

- `button[aria-label="Start a goal"]` (composer) and `[role="dialog"][aria-label="Start a goal"]` (the sheet) share a label, so qualify the selector by role. <!-- src: src/features/session/SessionChat.tsx:1784 --> <!-- src: src/features/goals/GoalSheet.tsx:743 -->
- Reaching `met` depends on the model actually creating `GOAL_DONE` within one iteration. Otherwise the goal ends `exhausted`, which is still a valid run of the loop.
- With text in the composer, the button builds the condition and work prompt from that text. A `/goal` draft is intercepted, never sent to the harness. <!-- src: src/features/session/SessionChat.tsx:1287 --> <!-- src: crates/hyprlayer-core/src/runtime/goals/mod.rs:873 -->
- An evaluator whose binary is missing renders disabled, with the problem in its row, and doesn't count toward the gate. <!-- src: src/features/goals/GoalSheet.tsx:1067 --> <!-- src: src/features/goals/GoalSheet.tsx:435 -->
- A command check's directory must be relative and inside the worktree. <!-- src: src/features/goals/GoalSheet.tsx:56 --> <!-- src: src/features/goals/goalChecks.ts:30 -->
- A new-session goal must run in a `general`, `research` or `implement` session; the server refuses the rest. <!-- src: crates/hyprlayer-core/src/runtime/goals/mod.rs:616 -->
- Only one live goal per session (`GoalActive`). <!-- src: crates/hyprlayer-core/src/runtime/goals/mod.rs:603 -->
- A codex harness switches the budget field to `Tokens`. <!-- src: src/features/goals/GoalSheet.tsx:132 --> <!-- src: src/features/goals/GoalSheet.tsx:707 -->
- Archiving the workstream stops its goals. <!-- src: crates/hyprlayer-core/src/runtime/workstreams.rs:1391 -->
- The controls depend on status: `met` has none, `exhausted` offers `Extend…` and `Start again…`, `stopped` and `failed` only `Start again…`. <!-- src: src/lib/domain/goals.ts:160 -->

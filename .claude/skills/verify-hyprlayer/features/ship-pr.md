# Ship and pull requests

Every Ship entry point opens one readiness dialog, `Ship <branch>?`. It names the ship harness and the base, and lists three rows (`Files viewed`, `Your comments`, `<agent>'s notes`) with jump links. Its primary button is `Ship`, or `Ship anyway` when a row isn't clear. Shipping runs the Ship agent, which commits, pushes and opens a PR. The Git panel then swaps `Attach an existing PR…` for the PR bar: `PR #N`, `Fix CI`, `Address comments`, `Merge`/`Auto-merge` with a method menu, and, once merged, `Archive`. The CI Checks panel lists the PR's checks, a merge conflict, or a required review. The Git panel also changes the target branch, pulls from the base and fetches the remote.

## Gotchas

- After `Chat` closes a review, the right aside comes back on `Plan`, which hides the Git panel and the changes list. Click `Changes` in the aside first.
- On a branch that is its own base (an in-place `main` tracking `origin/main`) with no local commits, the pull button fast-forwards the upstream instead: its label is `Pull <upstream>, fast-forwarding N commit(s) in`, and the separate behind-upstream row hides (#463). The sandbox branch isn't its own base, so `Update from main` still holds there. <!-- src: src/features/workstreams/GitPanel.tsx:34 -->
- Ship's enablement keys on `git.base.ahead`, not `git.ahead`, so a pushed but PR-less branch still shows Ship. <!-- src: src/features/workstreams/useGitActions.ts:69 --> Earlier runs faked the pushed state offline with `git update-ref refs/remotes/origin/<branch> HEAD`, undone with `-d` (from run memory).
- A failed PR probe, such as a spent GraphQL quota, now comes back as an error, not "no PR". The bar keeps the last known PR and retries every 60s. If the bar looks stale, check `gh api rate_limit --jq .resources.graphql`. Every running Hyprlayer instance draws on the same quota. <!-- src: crates/hyprlayer-core/src/runtime/workstreams.rs:928 --> <!-- src: src/lib/queries.ts:934 -->
- `Ship` and `Merge` appear in several places at once (Git panel, review header, lifecycle). Select by the container or the dialog's `aria-label`, not bare text.
- With `git.archiveOnMerge` set, a merge on the active workstream auto-archives it and leaves the page. Check the setting before testing `Archive` by hand. <!-- src: src/routes/Root.tsx:606 -->
- Enter in the Attach input attaches only a bare number (`#?\d+`). Click the row instead; Enter doesn't submit under the bridge. <!-- src: src/features/workstreams/AttachPrDialog.tsx:68 -->
- `Fix CI` and `Address comments` hand feedback to an agent on the branch: model turns and a push. They're live tier only. <!-- src: src/features/workstreams/PrStatusBar.tsx:124 -->
- `gh pr merge --delete-branch` run by hand switches checkouts, which can reload Vite and exit the dev app. Run doctor again after any manual `gh` merge. <!-- src: .claude/skills/verify-hyprlayer/SKILL.md:92 -->
- Raw `attach_workstream_pr`/`merge_workstream_pr` skip react-query invalidation. Use them only to seed, then reload before reading the UI. <!-- src: .claude/skills/verify-hyprlayer/SKILL.md:60 -->
